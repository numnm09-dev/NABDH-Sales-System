# نبض | شبكة الإمداد الذكية — NABDH

منصة ويب عربية (RTL) لمتابعة المخزون والموردين والمشتريات، وحساب فجوة التوريد، ومقارنة الانتظار بالشراء من مورد بديل.

**إعداد الطالب:** عبدالله محمد
**تحت إشراف:** د. آية الشافعي
**المعهد العالي للإدارة بالمحلة الكبرى**

> يمكن تعديل هذه البيانات من صفحة «الإعدادات» أو من `data/sample-data.json`. تأكّد من الاسم الكامل للمشرف قبل التسليم.

## ما الذي يعمل فعليًا
- إضافة/تعديل/حذف (مع تأكيد) الأصناف والموردين والطلبات، مع بحث وتصفية.
- أيام التغطية = الكمية ÷ الاستهلاك اليومي، وفجوة التوريد = وصول الشحنة − أيام التغطية.
- ترتيب الموردين البدلاء (35٪ سعر، 35٪ وقت، 30٪ جودة)، وكمية إعادة الطلب، ومقارنة الانتظار بالبديل.
- محاكاة (زيادة الطلب، تأخر الشحن، ارتفاع السعر) وتصدير CSV/JSON.
- **الحسابات رياضية بحتة (`js/calc.js`)، وتحليل الذكاء الاصطناعي نص تفسيري منفصل.**

## حدود مهمة
- جميع البيانات في `data/` **افتراضية**، والموردون «تجريبيون» أو «مرشحون يحتاجون إلى تأكيد». لا توجد أسعار أو مخزون مؤكد لأي مورد.
- الحفظ في `localStorage` للمتصفح، وهذا ليس بديلًا عن قاعدة بيانات آمنة متعددة المستخدمين.
- الذكاء الاصطناعي **غير متصل** حتى تنشر الخادم وتضبط المفتاح وتجرّب الاتصال.

## التشغيل محليًا
```bash
python3 -m http.server 8000   # ثم افتح http://localhost:8000
npm test                      # اختبارات الحسابات (Node 18+)
```

## النشر على GitHub Pages
1. أنشئ مستودعًا وارفع محتويات المجلد (لا ترفع `.env`).
2. Settings ← Pages ← Source: `main` / root ← Save.
3. افتح الرابط الظاهر.

## ربط الذكاء الاصطناعي ونشر الخادم (Vercel)
**ما الذي يحدث:** الواجهة ترسل بيانات الأصناف والموردين والطلبات إلى `api/analyze.js`. الخادم يحسب الأرقام بكود رياضي (`js/calc.js`)، ثم يطلب من النموذج تفسيرها فقط، ويُرجع JSON تعرضه الواجهة بالعربية. الخادم يحذف أي مورد يذكره النموذج وليس في بياناتك.

**خصوصية وتكلفة:** عند الضغط على زر التحليل تُرسل بياناتك إلى مزود النموذج، والاستخدام مدفوع حسب سعر المزود. لا ترسل بيانات حقيقية حساسة في النسخة التجريبية.

### الخطوات
1. أنشئ مفتاح API من حسابك لدى مزود النموذج، ولا تضعه في أي ملف داخل المستودع.
2. ارفع المشروع إلى GitHub (الملف `.gitignore` يمنع رفع `.env`)، ثم استورده في Vercel (Add New ← Project). ملف `vercel.json` مضبوط مسبقًا.
3. في Vercel: Settings ← Environment Variables أضف:
   - `ANTHROPIC_API_KEY` = مفتاحك
   - `AI_MODEL` = اسم نموذج متاح لحسابك
   - `ALLOWED_ORIGIN` = رابط واجهتك على GitHub Pages، مثل `https://USERNAME.github.io` (بلا شرطة في النهاية، ويمكن فصل أكثر من رابط بفاصلة)
4. اضغط Redeploy بعد إضافة المتغيرات.
5. افتح الواجهة ← الإعدادات ← ضع `https://اسم-مشروعك.vercel.app/api/analyze` ← احفظ ← اضغط «اختبار الاتصال».
6. افتح «تحليل المخاطر»، اختر «علب عصير» بتأخر 10 أيام، واضغط «اطلب تحليل الذكاء الاصطناعي».

### اختبار من سطر الأوامر
```bash
curl -X POST https://اسم-مشروعك.vercel.app/api/analyze -H "Content-Type: application/json" -d '{"ping":true}'
```
النتيجة المتوقعة: `{"ok":true,...}`. رموز الأخطاء: `not_configured` (متغيرات ناقصة)، `provider_auth` (مفتاح مرفوض)، `provider_model` (اسم نموذج خاطئ)، `rate_limited`، `timeout`، `bad_input`، `missing_data`.

### الاختبارات
`npm test` يشغّل اختبارات الحسابات واختبارات الخادم بمزود وهمي. هذه لا تثبت الاتصال الفعلي بالمزود؛ الاختبار الحقيقي هو الخطوة 5.

### تنبيه أمني
`ALLOWED_ORIGIN` يقيّد المتصفحات فقط، لكنه لا يمنع من يعرف رابط الخادم من استدعائه مباشرة. للاستخدام العام أضف تحديد معدل أو مصادقة وحدًّا للإنفاق في حساب المزود.
