# نبض | نظام ERP متكامل لشركة عصائر ومشروبات

منصة عربية (RTL، متجاوبة) تربط: المبيعات، المشتريات والموردين، المخازن والمخزون، الإنتاج، المحاسبة الأساسية، التقارير، وتحليل مخاطر الإمداد بالذكاء الاصطناعي (**الذكاء يوصي والإنسان يقرر**).
الواجهة ملفات ثابتة (تصلح لـ GitHub Pages)، البيانات على Firebase Realtime Database، وخادم الذكاء الاصطناعي اختياري على Vercel (`api/analyze.js`).

## هيكل المشروع
| الملف | الدور |
|---|---|
| `js/erp-core.js`, `erp-ops.js`, `erp-ops2.js` | محرك الأعمال: مخازن، سندات، دفتر حركة، BOM، إنتاج، موردون، أوامر شراء، استلام، مبيعات، مرتجعات، محاسبة، ترحيل، تدقيق |
| `js/store.js` | تنفيذ كل عملية داخل معاملة Firebase (`runTransaction`) مع منع التكرار بمعرّف عملية |
| `js/erp-reports.js`, `xlsx-lite.js` | التقارير وتصدير Excel/CSV |
| `js/ui-kit.js`, `ui-pages*.js`, `app.js` | الواجهة والتوجيه والدخول وشاشة الترقية |
| `js/calc.js`, `api/analyze.js` | حسابات المخاطر (SCMIS) وخادم الذكاء الاصطناعي (دون تغيير في العقد) |
| `database.rules.json` | قواعد أمان Firebase (**يجب نشرها**) |
| `tests/` | 92 اختبارًا (`npm test`) |

## التشغيل
1. `npm test` للتحقق (يتطلب Node 18+، بلا حزم خارجية).
2. انشر الواجهة على GitHub Pages أو أي استضافة ثابتة. `js/firebase.js` يحوي إعداد Firebase للويب وهو معرّف عام وليس سرًّا؛ الحماية الفعلية في قواعد قاعدة البيانات.
3. انشر `database.rules.json` من لوحة Firebase (Realtime Database ← Rules) أو `firebase deploy --only database`.
4. للذكاء الاصطناعي: انشر المشروع على Vercel وضع في إعداداته فقط: `GEMINI_API_KEY` و`AI_MODEL` و`ALLOWED_ORIGIN` (انظر `.env.example`)، ثم ضع رابط `/api/analyze` في صفحة الإعدادات. بدونه تعمل الحسابات الرياضية كاملة.

## الميزات المنفّذة (كلها مغطاة باختبارات المحرك أو الواجهة)
- **المخازن**: مخزن مواد خام منفصل عن المنتجات التامة؛ سندات استلام/صرف/تحويل/تسوية؛ دفتر حركة؛ تنبيه حد أدنى؛ **لا رصيد سالب**.
- **الإنتاج**: BOM، فحص توفر المواد، استهلاك وهالك، تكلفة، استلام منتج تام.
- **المشتريات**: موردون، أوامر شراء، استلام بضاعة (جزئي/كامل)، سداد الموردين.
- **المبيعات**: عملاء، فواتير بخصم تلقائي من المنتجات التامة، مرتجعات، تحصيلات.
- **المحاسبة**: إيرادات، مصروفات، خزينة، ذمم مدينة ودائنة، ملخص مالي وقيود.
- **التقارير**: مخزون، حركة، إنتاج، مبيعات، مشتريات، مالية، مخاطر AI، سجل المراجعة؛ مرشحات تاريخ؛ طباعة/PDF (عبر نافذة الطباعة)، CSV، Excel.
- **لوحة تنفيذية**، تحليل مخاطر + ذكاء اصطناعي مع اعتماد/رفض مسجَّل، محاكاة سيناريوهات، نسخة JSON احتياطية.
- **التدقيق**: كل تغيير يُسجَّل بمستخدمه ووقته؛ معرّف العملية يمنع التكرار.

## حدود معروفة (بصراحة)
- **التحقق يجري داخل المتصفح ضمن معاملة Firebase ذرّية، وليس على خادم.** القواعد تضمن عزل كل مستخدم ومنع الرصيد السالب لكل مخزن فقط؛ مستخدم يكتب مباشرة في بياناته يستطيع تجاوز بقية القواعد. التنفيذ الخادمي الكامل يحتاج حساب خدمة Firebase (firebase-admin) على Vercel أو Cloud Functions، وهو غير متوفر هنا.
- لم تُختبر القواعد على محاكي Firebase، ولم يُجرَّب الاتصال الحقيقي بخدمة الذكاء الاصطناعي، ولم تُجرَّب الواجهة في متصفح حقيقي (الاختبارات تستخدم DOM بديلًا ومحاكي Firebase). جرّب يدويًا: الدخول، الترقية، فاتورة، أمر إنتاج، طباعة تقرير.
- ملف PDF يُنشأ عبر «حفظ كـ PDF» من نافذة الطباعة، لا مولّد PDF مستقل.
